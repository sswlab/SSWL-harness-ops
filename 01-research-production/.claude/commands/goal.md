# /goal — 최대 노력 모드 (Maximum Effort Profile)

사용자가 `/goal $ARGUMENTS` 형태로 호출했습니다. 이는 연구 생산 파이프라인을
**최대 노력(maximum-effort)** 프로파일로 실행하라는 명시적 지시입니다.

> **핵심 분배**: 실험 설계·실행 단계에는 토큰·시간을 **공격적으로 투입**하고,
> 논문 작성 단계는 **초안 수준의 기존 구성을 유지**합니다 (논문 다듬기는 별도
> 사이클이나 `06-paper-editor` 하네스에서).

## 사용자 입력

```
$ARGUMENTS
```

위 텍스트를 연구 시드(주제·목적·작업경로 등)로 해석하여 `research-orchestrator`
스킬을 호출합니다. 아래 **강화 규칙**이 파이프라인 전체에 적용됩니다.

---

## 강화 규칙 (Maximum Effort Profile)

### A. 모드·명료성

1. **연구 모드는 무조건 `전체(Full Pipeline)`로 강제한다.** 사용자가 다른 모드를 명시했더라도 전체로 격상.
2. **Ambiguity 임계값을 ≤ 0.10 로 강화** (전체 모드 기본 0.20 → 0.10, 95% 명료). `intake-interviewer`는 임계값을 만족할 때까지 추가 라운드를 진행한다.
3. 누락된 시드 항목(주제/목적/작업경로)이 있으면 **한 번에 모두** 되묻고, 답을 받은 뒤 Phase 0로 진입한다.

### B. 사고 깊이·검증

4. **모든 에이전트는 thinking을 max로 사용한다.** (`--effort max` 상응 — 가능한 모델에서)
5. 각 Phase 종료 시 **self-critique 단계**를 추가한다.
   - "이 결과의 가장 약한 지점은? 누락된 가능성은? 반대 가설은?"을 스스로 던지고 답한다.
   - 자기 비판 결과를 해당 Phase 산출물 끝에 `## Self-Critique` 섹션으로 첨부한다.
6. **시간 제약을 의식하지 말 것.** 빠른 응답보다 깊이가 우선이다. "시간이 부족해서" 요약하거나 단축하지 마라.

### C. 문헌·검토 루프 (기존 유지)

7. **literature-reviewer**: 후보 논문 **최소 50편** 수집 → 중요도별 정리 (top 15는 상세 요약).
8. **reviewer 루프백 (Phase 4)**: 기존 **최대 2회 유지**. 실험 결과가 설계 의도에서 벗어나면 research-designer로 루프백.
9. **paper-writer 리비전 (Phase 5)**: 기존 구성 유지. **초안 수준**이 목표 — 과도한 다듬기 금지. reviewer 심사 1회 + 필요 시 짧은 리비전 정도면 충분.

### D. 실험 설계·실행 (강하게 밀어붙임 — `/goal`의 핵심)

10. **research-designer**: 한 가지 설계로 만족하지 말고 **대안 설계 ≥ 3개**를 제시한다. 각 설계마다 다음을 명시:
    - 검증할 가설 (Null vs Alternative)
    - 데이터·전처리·모델 선택지
    - 평가 지표·통계 검정·유의수준
    - 예상 실패 모드와 대비책
    설계들을 비교한 뒤 **하나를 선택**하되, 선택 근거를 설계 문서에 기록한다.

11. **research-executor**: 선택된 설계를 그대로 실행하지 말고 추가로 다음을 의무화:
    - **대안 방법 ≥ 3개** 병행 비교 (예: 다른 모델·전처리·하이퍼파라미터)
    - **Baseline 비교** 필수 (간단한 통계 모델, 선행연구 best 등 최소 2개)
    - **Ablation study** — 핵심 구성요소를 하나씩 제거/대체한 실험
    - **Sensitivity analysis** — 주요 하이퍼파라미터·전처리 선택의 결과 변동성 측정
    - **통계적 유의성 검증** — bootstrap CI / permutation test / cross-validation 중 적절한 것
    - **실패·반례 케이스** — 모델이 실패하는 입력 유형을 별도 보고

12. **연구 노트**: 실험마다 결과뿐 아니라 **선택 근거·반증 시도·재현 명령**을 `{작업경로}/research-note.md`에 누적 기록한다.

### E. 산출물 품질

13. 실험 단계의 Figure/Table은 **분석용 품질**로 생성 (한눈에 비교 가능하도록 baseline·대안·ablation 함께).
14. 논문 초안의 Figure/Table은 **초안 수준**이면 충분 (출판 품질까지 다듬을 필요 없음 — 후속 별도 사이클에서).
15. 모든 정량 주장에 **재현 가능한 출처**(코드 파일·셀·셀범위·데이터 해시)를 명시.

### F. 진행 보고

16. 각 Phase 시작/종료, self-critique, 루프백 발생 시점을 **진행 로그**로 사용자에게 실시간 보고한다. 사용자가 흐름을 끊을 필요가 없도록 자동으로 다음 단계로 진행.
17. 도중에 사용자 입력이 필요한 결정(예: 저널 선택)이 있다면 한 번에 모아서 묻는다.

---

## 실행 순서

1. 위 사용자 입력에서 **주제·목적·작업경로**를 추출. 누락 시 한 번에 되묻기.
2. 추출 완료되면 `research-orchestrator` 스킬을 호출하되, 다음 OVERRIDE 블록을 첨부:

   ```
   [GOAL-MODE OVERRIDE — STRICTLY ENFORCED]
   - 모드: 전체 (Full Pipeline) 강제
   - Ambiguity 임계값: ≤ 0.10
   - thinking: max (전 에이전트)
   - 각 Phase 종료 시 Self-Critique 섹션 추가
   - literature: 최소 50편 (top 15 상세 요약)
   - reviewer 루프백 (Phase 4): 최대 2회 (기존 유지)
   - paper-writer 리비전 (Phase 5): 기존 구성 (초안 수준, 다듬기 최소화)
   - research-designer: 대안 설계 ≥ 3개 비교 후 선택, 선택 근거 기록
   - research-executor: 대안 방법 ≥ 3개 + Baseline ≥ 2개 + Ablation + Sensitivity + 통계 유의성 검증 + 실패 케이스 보고
   - 산출물: 실험은 분석용 품질, 논문은 초안 수준
   - 시간 제약 없음 — 깊이는 Phase 2~3 (설계·실행)에 집중 투입
   ```

3. `research-orchestrator`는 이 OVERRIDE 블록을 각 에이전트 호출 프롬프트 맨 앞에 복제하여 전파한다.

## 사용자 통지

파이프라인 시작 직전, 사용자에게 한 줄로 통지한다:

> 🎯 **최대 노력 모드(Maximum Effort)**로 실행합니다 — 실험 설계·실행에 깊이 집중 (대안 ≥3개, ablation, sensitivity, 통계 검증), 논문은 초안 수준 유지. 시간 제약 없음. 결과까지 길게 걸릴 수 있습니다.

그 후 진행 로그를 자동으로 출력하며 다음 단계로 진행한다.
